# User Testing Task List - WaitLess App

## Task List

| # | Task Title | Instruction | Rationale |
|---|------------|-------------|-----------|
| 1 | **Login and Initial Discovery** | Log in to the WaitLess app using the provided test account. Once logged in, explore the main screen and identify at least 3 venues that appear in your area. What information can you see about each venue at first glance? | This simple one-action task tests basic authentication flow. It determines whether users can easily understand the app's purpose and navigate to view nearby venues. Want to observe how users view the venue list interface, the suggested venues section, and the visual indicators (wait times, crowd levels). |
| 2 | **Switch Between List and Map Views** | Switch to the map view to see venues displayed on a map. Compare what you see in map view versus list view. Can you find the same venues? Switch back to list view. Which view do you prefer and why? | This task tests navigation between different presentation modes, seeing if users can easily switch views and understand the relationship between list and map representations. It shows if users find one view more intuitive than another, and whether the map view provides enough context (location, relative positions) compared to the list. |
| 3 | **Examine Venue Details and Current Metrics** | Select a venue that interests you and view its detailed page. Examine the current metrics shown (wait time, crowd density, noise level, energy level). Try to understand what the data means and whether you think it's current and reliable. What information helps you decide if this venue matches what you're looking for? | This task tests viewing the venue detail interface and metrics. Want to understand whether users can interpret the metrics correctly (e.g., what does "moderate crowd" mean? Is a 15-minute wait acceptable?), whether they trust the data, and how they use it to make decisions. |
| 4 | **Submit a Wait Time Report** | Imagine you've just arrived at the venue you're viewing. Submit a wait time report indicating how long you waited (or are currently waiting). Walk through the reporting process - what information is requested? After submitting, observe how the venue's metrics update. | This task tests the reporting workflow, which is needed for the app's data collection. We want to observe if users understand what's being asked, if the geofence verification is clear or confusing, and if users can see the updated metrics.|
| 5 | **Submit a Vibe Report** | Now submit a vibe report for the same venue, describing the atmosphere: crowd density, noise level, energy level, and any music tags you notice. After submitting, check how this information appears in the venue's metrics section. | This task tests the vibe reporting system. We want to understand if users understand the different categories, if they find the options comprehensive, and if they understand how their report contributes to aggregated data. |
| 6 | **View Peak Time Forecast** | Navigate to a venue that has historical data. Find and examine the peak time forecast, when does the app predict this venue will be busiest? Use this information to plan when you might want to visit. Do you find the forecast helpful? Why or why not? | This task tests understanding of the peak forecasting feature. We want to observe: whether users can locate the forecast feature, if they understand what peak times mean for their decision-making, whether the presentation is clear, and if they trust predictions based on historical patterns.|
| 7 | **Set Up an Alert Subscription** | Imagine you want to be notified when your favorite venue's wait time drops below 10 minutes. Set up an alert for this condition. Walk through the process of creating the alert - is it clear what conditions you can set? After setting it up, how would you manage or modify this alert later? | This task tests the alert subscription system. This helps users take advantage of low wait times without constant checking. We want to observe if users can find where to create alerts, if the condition-setting interface is intuitive, and if they understand what triggers an alert. |
| 8 | **Compare Multiple Venues and Make a Decision** | You're planning a night out and need to choose between 3 different venues. Use the app to compare their current conditions (wait times, crowd levels, vibe). Consider the peak forecasts if available. Based on what you see in the app, which venue would you choose and why? Walk through your decision-making process. | This tests the user journey of using WaitLess to make an informed decision. We want to observe how users navigate between venues, if they can mentally compare metrics across venues, if they integrate multiple data points (current wait + forecast + vibe), and if the app provides enough information to make a confident decision. |
