# Reflections

## Jonathan

This was the first time I had created a large-scale app using primarily prompting and LLM tools. I quickly found out that LLMs are better when they are given precise, detailed instructions on the first try rather than constant prompting to debug. I learned how to use various services and frameworks common in the industry like Deno, Vue, and Render. Using an app like Cursor was extremely helpful because the AI agent was able to read through the entire codebase. 

## Anna
This project gave me a new perspective on working on complex projects with a group. From this experience I was able to learn more about what does and does not work collabritively on projects like this. Specficially, I think I got much better with effective communication. From a more technical perspective, learning how to effectively utilize LLM for coding was interesting. This project gave me a deeper understanding how to use Cursor. Becoming more comfortable with the skills and tools I learned on the individual project, especially for Render, was apparent and useful. 

## Stephen
I think the best part of building WaitLess was watching people try to use and test it. After the user testing, I realized developers and users think completely differently, and I can't assume some feature was obvious. The geofence verification was built to prevent fake reports, but we never actually explained to users why they needed to be at the venue. We made something that worked but did not make sense to people. Working with team taught me that people have different strengths and weaknesses, and communication is extremely important for collaboration. The user testing debriefs were especially helpful and hearing people explain their thought process was very valuable. This experience showed me that building a good product requires understanding the end user's perspective.

## Dylan

While building WaitLess, it was hard to get the frontend and backend to actually work together sometimes. After designing an API endpoint, the frontend would need the data in a different format, so we would spend time adjusting one side to match the other. I also spent a lot of time making the frontend look nice and polished, focusing on things like spacing, color schemes, and making sure buttons and forms were visually appealing. I enjoyed seeing the app transform from a basic functional interface into something that actually looked professional. The biggest thing I learned is that getting something working matters more than getting it perfect. I prioritized creating a clean frontend to make the app feel more complete. Working with other people taught me that collaboration requires clear communication and being open to different perspectives and approaches to solving problems.
